# Tehran housing market data — cleaned from a mixed transcript archive

This folder is the cleaned, production-ready output of
`data/raw/rent-data-donyaeghtesad.rtf`, generated by `scripts/parse_rent_rtf.py`
(standard library only, deterministic — reruns produce byte-identical CSVs).

**The input is not one dataset.** It is an LLM-conversation transcript whose own header says it
holds *"all the raw data extracted and transcribed from every image and text prompt throughout
this conversation"*, and it warns against combining timeframes. It contains **8 source tables in
12 markdown tables**, spanning rent listings, sale listings and district statistics from several
different origins. The input file keeps its original (misleading) name as an audit artefact; the
output folder is named neutrally on purpose.

Input: 59,504 bytes · `sha256 4569c6eed6b8…` · 419 text lines · 12 table headers.

## Pipeline

```
raw archive (RTF, unchanged, committed)
        ↓ deterministic parser            scripts/parse_rent_rtf.py
observations/  (everything, minus exclusions)
        ↓ quality flags + classes
datasets/      (publication files, one per source table, provenance in the name)
excluded/      (material that must not be used)
parse_report.json  (provenance, evidence, every anomaly)
```

Row conservation is exact: the source contains **323 table data rows** (counted independently
from the extracted text) and the outputs contain **344 rows**, because dataset 1's 21 rows each
carry two price bases (estimated / newly built).
`210 rent + 82 sale + 23 district-stat + 29 excluded = 344`.

## ⛔ Excluded material

**Dataset 7 (29 rows) is not in any production file.** It is published only under `excluded/`,
with `excluded_reason = "simulated / unreliable provenance (the transcript labels it 'Simulated
web research from fardayeeghtesad.com')"` written into every row and `evidence_tier = D`. It is
not merely tagged inside the main CSV, because a downstream analyst could overlook a tag; if you
load `observations/*`, you cannot load dataset 7 by accident.

Verified: zero dataset-7 rows appear in `observations/` or `datasets/`.

## Naming policy (provenance is part of the name)

Publication files are named **measurement kind + date**, and carry the outlet **only where the
transcript names one**. A file is never named after an outlet we cannot verify.

Consequence for the requested names: **`rent_asking_donyaye_eghtesad_1401_1405.csv` and
`sale_price_official_1402.csv` cannot be produced from this source.** There is no Donya-e-Eqtesad
table anywhere in this file — the only outlet named is *Fardayeeghtesad*, and that is the
simulated block, now excluded. Dataset 6 (Aban 1402 district averages with transaction counts)
*looks* like an official/SCI-style table, but its origin cannot be established from the
transcript, so it is published as
`sale_price_district_avg_1402-08_origin_unverified.csv`.

The dated, reproducible Kilid sale series that would fill `sale_price_kilid_1400_1405.csv` already
exists in this repo at **`kilid/kilid_data/`** (10 cities, 117 areas, 4,959 monthly rows); it is
not duplicated here.

## Quality flags — three-way classification

Every flag is a class, not just a note. `issue_classes` on each row carries the classes that apply;
`flag_amount_ambiguous` is `TRUE` whenever the amount could not be trusted as written.

| Class | Meaning | Policy | Instances |
| --- | --- | --- | --- |
| `data_error` | the pipeline can prove and fix it | **must not survive** — all six parser bugs found here were fixed | **0 remaining** |
| `source_ambiguity` | the source itself does not say clearly | value stays empty (or min/max), flag stays | 10 |
| `source_anomaly` | looks strange but may be real | keep the value, flag it, never remove it | 1 |
| `notation` | recorded assumption / notation, not a defect | no action needed | 20 |

The six `data_error`s are listed in `parse_report.json → parser_fixes`: Persian digits being
swallowed by `\d` (which destroyed 108 district cells), surrogate-pair decoding, multi-unit sums
(`62 میلیون و 500 هزار` → 562,000,000 instead of 62,500,000), range unit inheritance
(`12 الی 32 میلیون`), Persian decimal slashes (`1/2 میلیارد` read as a range 1–2), and Persian
word-numbers (`یک میلیون`).

## Dataset 4 reconciliation (Tir 1403)

The review question was whether dataset 4 is really a sale table (recall was a **rent** table for
70–100 m²). **Verdict: sale price per m², not rent.** Evidence, all reproducible from the report:

* the column header is `قیمت هر مترمربع (تومان)` — price per square metre;
* the transcript title is *"Suggested sales prices for residential apartments in Tehran."* and its
  own note says *"This is Sales data, not Rent data."*;
* magnitudes are tens-to-hundreds of millions of toman **per m²**, while every rent row in this
  archive is 700,000–85,000,000 toman **per month** plus a separate deposit;
* it is not restricted to 70–100 m²: floor areas span **36–315 m²**.

The archive *does* contain a rent table for larger apartments, but that is dataset 3 (Aban 1404,
≈70–140 m²). **No Tir 1403 rent table exists in this file**, so the 40 records stay in
`sale_observations.csv` and nothing was moved.

## Rent and sale are never interconverted

`rent_*` columns are observed asking rents only; `sale_*` / `price_psm_*` columns are observed
asking sale prices only. **No value in this output is derived from the other**, and no rent is
implied from any sale price. The two families live in different files and different observation
tables (`rent_observations.csv` vs `sale_observations.csv`), so they can be compared later —
spatially and explicitly — without manufacturing one from the other.

## Methodology is frozen

The parsing rules are considered frozen. New work should be *additions*, not re-tuning:
if a new source problem appears, add a flag class and document it in `parse_report.json`; do not
silently change a rule that would move existing values. `parser_fixes` exists precisely so a
reader can see what changed and when.

## Columns (raw + parsed are always kept side by side)

| Raw (as written in the source) | Parsed |
| --- | --- |
| `deposit_raw`, `rent_raw` | `deposit_toman` (+ `_min`/`_max`), `rent_toman` (+ `_min`/`_max`), `rent_is_free` |
| `price_psm_raw` | `price_psm_toman`, `price_psm_unit_source` |
| `building_age_text` | `building_age_years` |
| `price_avg_million_rials` | `price_psm_toman` (×100,000) |

Provenance on every row: `dataset_id`, `dataset_title`, `sub_table`, `source_kind`, `source_label`,
`evidence_tier`, `verification`, `date_jalali_raw`, `date_jalali_ym`, `date_status`,
`geography_level`, `source_row` (line number in the transcript), `flag_amount_ambiguous`,
`issue_classes`, `notes`.

Unit rules: money is written in **toman**; `میلیون` ×10⁶, `میلیارد` ×10⁹, `هزار` ×10³,
`million` ×10⁶; a bare number takes its column header's unit; `الی` produces min/max; `رایگان`
produces `0` with `rent_is_free = TRUE`; `نوساز` leaves the age empty with `building_age_text`
and the `age_new_build` notation; a dash stays empty (the source had no value).
